# 어색한 표현 매칭표

한국어 문서에서 실제로 나온 어색한 표현과 고친 표현을 모은 표다. 규칙은 [principles.md](principles.md)의 "낱말" 절(규칙 19~26)에 있고, 이 문서는 그 규칙의 사례 대장이다. 문서를 검토하며 새 표현을 찾을 때마다 줄을 더한다.

## 언제 적용하나

- 사람이 읽을 한국어 문서를 다 쓴 뒤, 왼쪽 열의 낱말로 문서를 검색한다. 걸린 곳마다 뜻을 확인하고, 표의 뜻으로 쓰인 곳만 오른쪽 열로 고친다. 같은 낱말이 다른 뜻으로 쓰인 곳과 인용문, 로그 문자열은 그대로 둔다.
- 문서를 검토하다가 표에 없는 어색한 표현을 찾으면 해당 유형의 표에 한 줄을 더한다.
- 작업 원본(명세서, log, 측정 원본)은 검색 대상이 아니다.

## 규칙

표의 "고친 표현"은 그 문맥에서 고른 말이다. 같은 낱말이라도 문맥이 다르면 다르게 고친다. 기준은 규칙 26의 판별 질문이다.

### 유형 3 - 한자어 명사로 뭉친 보고서 말투

영어 직역은 아니지만 같은 문서에서 함께 나오는 유형이다. 동작을 한자어 명사로 뭉치고 "~하였으며", "~를 통해"로 이으면 누가 무엇을 했는지 흐려진다(규칙 10).

| 어색한 표현 | 고친 표현 | 나온 문서 |
|---|---|---|
| 구현하였으며, 구성했습니다 | 실행합니다, 저장합니다 (실제 동작으로) | 팀 포트폴리오 |
| 영속화하여 추적 가능하게 구성 | 저장해 추적할 수 있게 | 팀 포트폴리오 |
| 가시화했습니다 | 볼 수 있게 됐습니다 | 팀 포트폴리오 |
| 체득한 경험이었습니다, 체감한 경험이었습니다 | 배웠습니다, 직접 겪었습니다 | 팀 포트폴리오 |
| 재정립하여 실행 원자성을 확보 | 순서를 바꿨습니다 | 팀 포트폴리오 |
| 체계를 구축했습니다 | 할 수 있게 됐습니다 | 팀 포트폴리오 |
| 강결합이 발생하고 | 강하게 결합되고 | 팀 포트폴리오 |
| 책임 경계를 재정의했습니다 | 나누고, 정했습니다 | 팀 포트폴리오 |
| 확장 가능한 기반을 마련 | 이벤트만 추가하면 됩니다 | 팀 포트폴리오 |
| 업무 편중, 부하 균등화를 통해 운영 효율성을 향상 | 한 사람에게 몰리지 않게, 배송량이 고르게 나뉘었습니다 | 팀 포트폴리오 |
| 전략 수립 | 방식 선택 | 팀 포트폴리오 |
| 도출했습니다 | 정했습니다 | 팀 포트폴리오 |
| 내재화했습니다 | 안에 넣었습니다 | 팀 포트폴리오 |
| 존재했지만, 혼재해 있었으며, 일관성을 잃었습니다 | 있었지만, 섞여 있었고, 제각각이 됐습니다 | 리팩토링 사례 |
| 인수인계 시, 착수 시 | 인수인계할 때, 시작할 때 | 리팩토링 사례 |

| 0실패 | 실패 0건 | 리팩토링 사례 |
| 종속시키므로 | 따라 정해지므로 | 부하테스트 사례 |
| 억제해 | 줄여 | 관제 사례 |
| 가장 큰 난관이었습니다 | 가장 어려웠습니다 | 유사 상표 검색 사례 |

### 바꾸지 않는 말 (규칙 21, 22)

검색에 걸려도 고치지 않는 말이다. 이미 통용되거나 문맥상 평범한 한국어다.

| 표현 | 이유 |
|---|---|
| 대조군, 임계 구역, 오탐, 정합성, 교란변수, 수확 체감, 임계점 | 자리 잡은 용어 |
| 되돌리다, 건너뛰다, 띄우다, 돌리다(테스트를) | 평범한 한국어 동사 |
| probe, prod, dev, staging, yml, upsert, flush, precheck, force merge, blue/green | 현업에서 영어 그대로 쓰는 말. 한글로 음차하거나 풀어 옮기지 않는다 |
| 승격(공용 패키지로) | 개발자가 실제로 쓰는 말 |
| 캐시 오염, 컨텍스트 오염 | cache pollution의 통용 번역 (측정 노이즈 뜻의 "오염"과 다르다) |
| 정산 대조 | 결제 도메인에서 쓰는 말 (카운터 보정 뜻의 "대조"와 다르다) |
| 6칸 (하네스 명세서의 필수 6칸) | 하네스가 정한 이름. "셀"로 바꾸지 않는다 |
| 꼬리표, 미끼, 고정비 | 뜻이 바로 통하는 평범한 한국어 |
| 몫(~의 몫), 갈래, 줄을 선다, 한도에 붙는다, 밀린다, 살아 있는, 번짐 | 은유지만 한국어에서 그 뜻으로 쓰는 말 |
| 엄격 한계, 포화점, 반감, 최저점 | 문서 안에서 정의한 측정 지표 이름. 바꾸지 않고 용어 표에 뜻을 단다 |
| 훑다 (학습 노트에서 본인 설명) | 평범한 한국어. 설계 문서의 scan 뜻일 때만 "스캔"으로 |

### 뜻이 여러 갈래인 낱말 (문서를 보고 뜻을 먼저 가른다)

같은 낱말이 문서마다 다른 개념을 가리킨다. 표의 왼쪽 열로 검색한 뒤, 걸린 곳의 뜻을 보고 고친다.

| 낱말 | 뜻 | 처리 |
|---|---|---|
| 기준선 | baseline (비교 기준이 되는 구현이나 측정값) | 베이스라인 |
| 기준선 | 임계 금액, 마감 시각 같은 경계선 | 그대로 둔다 (실측: 무료 배송 기준선, VACUUM 기준선) |
| 기준선 | 글자 기준선 (CSS, 조판) | 그대로 둔다. 자리 잡은 용어다 |
| 문턱 | threshold | 임계값 |
| 문턱 | 함수나 모듈의 경계 ("함수 문턱에서") | 그대로 둔다 |
| 어긋남 | 값의 불일치, mismatch | 불일치 |
| 어긋남 | clock skew | 클럭 스큐 |
| 어긋난다 (동사) | 시각, 예측이 맞지 않는다 | 그대로 둔다. 평범한 한국어다 |
| 판정기 | 정합성을 확인하는 도구 | 정합성 검증기, 판정 스크립트 |
| 판정기 | decider (계산 이론) | 그대로 둔다. 자리 잡은 용어다 |
| 안전망 | 주기적 전체 스캔 (fallback scan) | 폴백 스캔 |
| 안전망 | 테스트 안전망 (safety net) | 그대로 둔다. 리팩토링에서 통용되는 말이다 |
| 바퀴 | full scan 1회 | 풀 스캔 1회 |
| 바퀴 | 루프 한 바퀴 (iteration) | 그대로 둔다. 학습 노트의 평범한 표현이다 |
| 대조 | reconcile / 비교 / 대조군 / 양성 대조 | 앞의 둘만 보정, 비교로 바꾼다 |
| 무음 | silent (실패, 유실, 통과) | 조용한 실패, 조용히 유실된다 |
| 손잡이 | 조절할 수 있는 설정값 (knob) | 조절 수단. 랩 문서에서는 설정 옵션 |
| 손잡이 | 나중에 결과를 받거나 대상을 가리키는 참조 (handle) | 핸들 |
| 손잡이 | 문, 서랍, 슬라이더의 실제 손잡이와 그것을 쓴 비유 | 그대로 둔다 |
| 창 | 확인 방법의 종류 (문서 묶음의 고유 낱말) | 확인 방법 |
| 창 | 브라우저 창, 주소창, 시간 창(배포 창, 고정 창) | 그대로 둔다 |

### 유형 5 - 문서 묶음 안에서만 통하는 고유 낱말

영어 직역은 아니지만, 한 문서 묶음을 쓰다가 굳어진 말이다. 쓴 사람과 그 묶음을 읽어 온 사람만 안다. study-note의 언어 노트(약 2,800개)에서 나왔다.

| 어색한 표현 | 뜻 | 고친 표현 |
|---|---|---|
| 흔들린다, 안 흔들린다 | 실행할 때마다 결과가 달라진다, 같다 | 실행마다 달라진다, 달라지지 않는다 |
| 흔들리는 칸, 안 흔들리는 칸 | 실행마다 달라지는 값, 고정된 값 | 실행마다 달라지는 항목, 달라지지 않는 항목 |
| 이 판(7.0.2), 판이 오르면 | 도구의 버전 | 이 버전(7.0.2), 버전이 오르면 |
| 캡처를 세 판 돌려 | 실행 횟수 | 캡처를 세 번 돌려 |
| 던진 것, 안 던졌다, 던져서 받은 | 입력을 넣어 실행했다 | 실행한 것, 실행하지 않았다, 실행해서 받은 |
| 갈렸다, 안 갈렸다 | 결과가 달라졌다 | 달라졌다, 달라지지 않았다 |
| 둘로 갈린다 | 나뉜다 | 둘로 나뉜다 |
| 부적용 | 해당 없음 | 해당 없음 |
| 이 주제의 본체 | 핵심 | 이 주제의 핵심 |
| 이 주제가 쓰는 창, 핵심 창, 3창(...) | 무엇을 보고 확인했는가 | 이 주제가 쓰는 확인 방법, 핵심 확인 방법, 3번 확인 방법(...) |

같은 낱말의 다른 뜻은 바꾸지 않는다.

| 그대로 두는 쓰임 | 이유 |
|---|---|
| 예외를 던진다, 직접 던진 예외 | throw의 통용 번역 |
| 함수 본체, 루프 본체 | body의 통용 번역 |
| 흔들림 (jitter, 측정값의 변동) | 다른 개념. cs 노트에서는 지터, 변동의 뜻이다 |
| 헷갈리는, 엇갈린 | 다른 낱말 |
| 재다, 쟀다, 재지 않았다 | 평범한 동사 |

### 치환할 때 생긴 사고 (다시 하지 않기 위한 기록)

낱말만 바꾸면 문장이 깨지거나 뜻이 바뀐다. 아래는 실제로 생겼다가 고친 것이다.

| 사고 | 원인 | 막는 법 |
|---|---|---|
| "카운터가 불일치가 생기면" (주어 겹침) | "어긋나면"을 낱말만 바꿈 | 동사를 명사로 바꿀 때는 문장을 다시 쓴다 |
| "분포의 테일 레이턴시" | "꼬리"가 지연이 아니라 분포의 끝을 뜻한 곳 | 같은 낱말의 다른 뜻을 먼저 조사한다 |
| "6셀" (하네스의 "필수 6칸") | "칸"을 모두 "셀"로 바꿈 | 다른 문서가 정한 이름은 치환 대상에서 뺀다 |
| "한 트랜잭션에 따라 달라진다" | "묶인다"가 '함께 잡힌다'는 뜻인 곳 | 치환 뒤 바뀐 줄을 유형별로 표본을 뽑아 읽는다 |
| "키은", "스캔를" | 받침이 달라졌는데 조사를 그대로 둠 | 치환할 때 조사를 받침에 맞춘다 |
| "예외로 실행했다" | "던졌다"가 실행이 아니라 throw인 곳 | 치환한 줄을 원본 줄과 비교해, 원본에 예외 낱말이 있으면 되돌린다 |
| "실행 간 차이(jitter)" | "흔들림"이 지터를 뜻한 곳 | 폴더마다 낱말의 뜻이 다르다. 한 폴더에 먼저 적용해 읽어 본다 |
| "스파이크 초기 구간" | "느린 초"가 "느린 초기"의 앞부분과 겹침 | 낱말 경계를 규칙에 넣는다 |
| "핵심다" | "본체다"의 받침이 달라짐 | 서술격 조사(이다)도 받침에 맞춘다 |
| "기본 확인 방법 780" | "기본 창"이 브라우저 창 폭을 뜻한 곳 | 꾸미는 말이 붙은 꼴만 규칙에 넣고, 홀로 쓰인 꼴은 뜻을 보고 고친다 |
| 굵은 글씨 태그 짝 깨짐 | 태그가 낀 문장을 통째로 치환 | 태그를 보존하고, 치환 뒤 태그 개수를 센다 |

### 유형 4 - 작업하며 붙인 줄임 이름을 그대로 내보낸 것

작업 중에 선택지와 조건에 붙인 별명은 쓴 사람만 안다. 독자용 문서에서는 뜻을 풀어 쓰거나 첫 등장에 정의한다.
