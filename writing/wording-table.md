# 어색한 표현 매칭표

한국어 문서에서 실제로 나온 어색한 표현과 고친 표현을 모은 표다. 규칙은 [principles.md](principles.md)의 "낱말" 절(규칙 19~26)에 있고, 이 문서는 그 규칙의 사례 대장이다. 문서를 검토하며 새 표현을 찾을 때마다 줄을 더한다.

## 언제 적용하나

- 사람이 읽을 한국어 문서를 다 쓴 뒤, 왼쪽 열의 낱말로 문서를 검색한다. 걸린 곳마다 뜻을 확인하고, 표의 뜻으로 쓰인 곳만 오른쪽 열로 고친다. 같은 낱말이 다른 뜻으로 쓰인 곳과 인용문, 로그 문자열은 그대로 둔다.
- 문서를 검토하다가 표에 없는 어색한 표현을 찾으면 해당 유형의 표에 한 줄을 더한다.
- 작업 원본(명세서, log, 측정 원본)은 검색 대상이 아니다.

## 규칙

표의 "고친 표현"은 그 문맥에서 고른 말이다. 같은 낱말이라도 문맥이 다르면 다르게 고친다. 기준은 규칙 26의 판별 질문이다.

### 유형 2 - 영어 표현을 직역한 은유 (규칙 25)

표는 직역한 표현, 원래 영어 표현, 풀어 쓴 표현을 한 줄씩 보여 준다.

| 어색한 표현 | 원래 표현 | 고친 표현 | 나온 문서 |
|---|---|---|---|
| 이긴 요청, 진 쪽, 누가 이기나 | winner, loser | 성공한 요청, 실패한 요청, 경합을 어떻게 처리하나 | 좌석 실험 포트폴리오 |
| 누르면 | click | 요청하면 | 좌석 실험 포트폴리오 |
| 벽, 벽에 부딪힘 | hit a wall | 처리량 급락 | 좌석 실험 포트폴리오, 이력서 |
| 무너짐 (처리량) | collapse | 처리량이 급락함 | 좌석 실험 포트폴리오 |
| 강하게 지지 | strongly supports | 유력한 원인으로 본다 | 좌석 실험 포트폴리오 |
| 결정을 가른 근거 | deciding evidence | 결정 근거 | 좌석 실험 포트폴리오 |
| 비교할 바닥 | floor to compare against | 비교 기준이 될 설정 | 좌석 실험 포트폴리오 |
| 오염 | contamination | 측정 노이즈 | 좌석 실험 포트폴리오 |
| 흔들림과 가를 수 없는 | cannot tell from noise | 오차인지 차이인지 구분할 수 없는 | 좌석 실험 포트폴리오 |
| 다른 부하로 넓히지 않는다 | do not generalize | 다른 부하 조건에도 해당한다고 보지 않는다 | 좌석 실험 포트폴리오 |
| CPU가 거의 놀았다 | sat idle | CPU 사용률이 1.7%에 그쳤다 | 좌석 실험 포트폴리오 |
| 감수한 대가, 있는 그대로 남긴 것 | trade-off, limitation | 트레이드오프, 한계 | 좌석 실험 포트폴리오 |
| 무음 실패 | silent failure | 조용한 실패 | 좌석 실험 포트폴리오 |
| 억울한 거절 | unfair rejection | 다른 사용자가 좌석을 놓치는 일 | 이력서 |
| (고칠 곳에) 닿았다 | reached | 도달했다, 찾았다 | clean-code 실험 결론 문서 |
| 탐색 비용을 묶는다 | bounds | 탐색 비용을 제한한다 | graph-nav 실험 README |
| 잠금을 쥔다 | holds a lock | 잠금을 잡는다 | clean-code 실험 ADR |
| stderr 꼬리 | tail of output | stderr 끝부분 | clean-code 실험 ADR |
| 평평했다 | was flat | 차이가 없었다 | 부하테스트 사례 |
| 그 안에 묶인다 | bounded by | 그 수를 넘지 못한다 | 부하테스트 사례 |
| 무엇에 귀속해야 할지 | attribute to | 무엇 때문인지 | 부하테스트 사례 |
| 이 처치는 | this treatment | 이렇게 하면 | 부하테스트 사례 |
| 지배적이다 | dominant | 대부분을 차지한다 | 검색 지연 사례 |
| 한 곳에 집중시켜야 한다 | centralize | 보고 제어하는 곳이 하나여야 한다 | 팀 포트폴리오 |
| 어려움이 응축되는 영역 | concentrated | 어려움이 대부분 모여 있는 영역 | 팀 포트폴리오 |

### 유형 3 - 한자어 명사로 뭉친 보고서 말투

영어 직역은 아니지만 같은 문서에서 함께 나오는 유형이다. 동작을 한자어 명사로 뭉치고 "~하였으며", "~를 통해"로 이으면 누가 무엇을 했는지 흐려진다(규칙 10).

| 어색한 표현 | 고친 표현 | 나온 문서 |
|---|---|---|
| 구현하였으며, 구성했습니다 | 실행합니다, 저장합니다 (실제 동작으로) | 팀 포트폴리오 |
| 영속화하여 추적 가능하게 구성 | 저장해 추적할 수 있게 | 팀 포트폴리오 |
| 가시화했습니다 | 볼 수 있게 됐습니다 | 팀 포트폴리오 |
| 체득한 경험이었습니다, 체감한 경험이었습니다 | 배웠습니다, 직접 겪었습니다 | 팀 포트폴리오 |
| 재정립하여 실행 원자성을 확보 | 순서를 바꿨습니다 | 팀 포트폴리오 |
| 체계를 구축했습니다 | 할 수 있게 됐습니다 | 팀 포트폴리오 |
| 강결합이 발생하고 | 강하게 결합되고 | 팀 포트폴리오 |
| 책임 경계를 재정의했습니다 | 나누고, 정했습니다 | 팀 포트폴리오 |
| 확장 가능한 기반을 마련 | 이벤트만 추가하면 됩니다 | 팀 포트폴리오 |
| 업무 편중, 부하 균등화를 통해 운영 효율성을 향상 | 한 사람에게 몰리지 않게, 배송량이 고르게 나뉘었습니다 | 팀 포트폴리오 |
| 전략 수립 | 방식 선택 | 팀 포트폴리오 |
| 도출했습니다 | 정했습니다 | 팀 포트폴리오 |
| 내재화했습니다 | 안에 넣었습니다 | 팀 포트폴리오 |
| 존재했지만, 혼재해 있었으며, 일관성을 잃었습니다 | 있었지만, 섞여 있었고, 제각각이 됐습니다 | 리팩토링 사례 |
| 인수인계 시, 착수 시 | 인수인계할 때, 시작할 때 | 리팩토링 사례 |
| ~를 진행했습니다 | ~했습니다 | 리팩토링 사례, 검색 지연 사례 |
| 확정하고, 축적해 | 정하고, 쌓아 | 리팩토링 사례 |
| 0실패 | 실패 0건 | 리팩토링 사례 |
| 종속시키므로 | 따라 정해지므로 | 부하테스트 사례 |
| 억제해 | 줄여 | 관제 사례 |
| 가장 큰 난관이었습니다 | 가장 어려웠습니다 | 유사 상표 검색 사례 |
| 의도적으로 배제했습니다 | 일부러 쓰지 않았습니다 | 유사 상표 검색 사례 |
| 저장함으로써 최소화했습니다 | 저장해 최소한으로 줄였습니다 | 유사 상표 검색 사례 |

### 바꾸지 않는 말 (규칙 21, 22)

검색에 걸려도 고치지 않는 말이다. 이미 통용되거나 문맥상 평범한 한국어다.

| 표현 | 이유 |
|---|---|
| 대조군, 임계 구역, 오탐, 정합성, 교란변수, 수확 체감, 임계점 | 자리 잡은 용어 |
| 되돌리다, 건너뛰다, 띄우다, 돌리다(테스트를) | 평범한 한국어 동사 |
| upsert, flush, precheck, force merge, blue/green | 통용 표기가 없는 원어 |
| 승격(공용 패키지로) | 개발자가 실제로 쓰는 말 |
| 캐시 오염, 컨텍스트 오염 | cache pollution의 통용 번역 (측정 노이즈 뜻의 "오염"과 다르다) |
| 정산 대조 | 결제 도메인에서 쓰는 말 (카운터 보정 뜻의 "대조"와 다르다) |
| 6칸 (하네스 명세서의 필수 6칸) | 하네스가 정한 이름. "셀"로 바꾸지 않는다 |
| 꼬리표, 미끼, 고정비 | 뜻이 바로 통하는 평범한 한국어 |
| 훑다 (학습 노트에서 본인 설명) | 평범한 한국어. 설계 문서의 scan 뜻일 때만 "스캔"으로 |

### 유형 4 - 작업하며 붙인 줄임 이름을 그대로 내보낸 것

작업 중에 선택지와 조건에 붙인 별명은 쓴 사람만 안다. 독자용 문서에서는 뜻을 풀어 쓰거나 첫 등장에 정의한다.

| 어색한 표현 | 고친 표현 | 나온 문서 |
|---|---|---|
| A(만료 배치 쌍 단위 견딤)+C(앱 안 대조) | 만료 배치는 실패한 키만 스킵, 앱 내 보정 배치 | 좌석 랩 README |
| ④ `conditional-extend` + ⓒ payBy(W 611초 · θ 1초) | 결제 시작 시 홀드 연장 + 결제 마감 시각 | 좌석 랩 README |
| L2, S4, S7-m1 (조건과 시나리오 번호만) | 앱과 DB에 CPU 2개를 준 조건, 초당 요청 수를 단계적으로 올리는 시나리오 (용어 표로 정의) | 좌석 랩 README |
| 문서 첫 화면의 진행 상황 기록 3,500자 | 저장소 소개 한 문단 + 상태 한 줄 | 좌석 랩 README |

## 예외

- "나온 문서" 열은 추적용이다. 표현이 그 문서에만 해당한다는 뜻이 아니다.
- 코드 식별자, 설정 키, 로그 문자열 안의 낱말은 고치지 않는다.
