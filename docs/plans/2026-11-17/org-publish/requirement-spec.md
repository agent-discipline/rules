## 1. 목표·대상 (필수)

`agent-discipline` 조직에 아래 저장소를 **같은 이름의 새 public 저장소**로 만들고 이력을 push한 뒤, 로컬 clone의 `origin`을 조직 주소로 바꾼다. 개인 계정(junhyeong9812) 저장소는 그대로 둔다.

| # | 저장소 | 현재 원격 | 올릴 범위 |
|---|---|---|---|
| 1 | claude-rules | 개인 public | 원격 브랜치 1개 |
| 2 | claude-code-harness | 개인 public | 원격 브랜치 8개 |
| 3 | clean-code-llm-experiment | 개인 public | 원격 브랜치 21개 |
| 4 | graph-nav-experiment | 개인 public | 원격 브랜치 6개 |
| 5 | compare-issue-archive | 개인 public | 원격 브랜치 3개 |
| 6 | need-haness-lab | 원격 없음 | 커밋된 이력만(브랜치 `setup/payment-experiment`, 6커밋) — **공개 안전 점검 통과 후에만** |

- 1~5: 개인 계정 원격에 **이미 공개된 브랜치·태그만** 올린다(로컬 전용 브랜치는 올리지 않는다). 설명 문구와 기본 브랜치는 개인 계정 것과 같게 한다.
- 6: 워커의 공개 안전 점검(시크릿·개인정보·대용량) 결과를 사용자에게 보고하고 확인받은 뒤 올린다. 미커밋·untracked 파일은 올리지 않는다.
- 실험 재개(30회 실행)는 **이 명세의 범위가 아니다** — 워커 조사 결과로 `need-haness-lab` 쪽에 별도 명세를 합의한다.

## 2. 경계·불변식 (필수)

- 개인 계정 저장소 5개는 내용·설정·공개 범위 모두 변하지 않는다.
- 로컬 저장소의 커밋·작업 트리·브랜치는 변하지 않는다. 바뀌는 것은 `origin` 주소(6번은 `origin` 추가)뿐이다.
- 조직 저장소의 모든 브랜치·태그 SHA는 개인 계정 원격의 같은 이름 ref와 일치한다(1~5).
- force push를 쓰지 않는다. 새 빈 저장소에 대한 일반 push만 한다.

## 3. 기준소스 (필수)

개인 계정 원격(`github.com/junhyeong9812/<이름>`)의 현재 ref 목록과 저장소 설명. 6번은 로컬 저장소의 커밋된 이력.

## 4. 금지영역 (필수)

- 개인 계정 저장소의 삭제·보관(archive)·이름 변경·내용 수정.
- 문서 속 개인 계정 주소 수정(README 등) — 별도 작업.
- 로컬 폴더 이동, `.github` 프로필 저장소 생성 — 별도 작업.
- need-haness-lab의 미커밋 변경을 커밋·stash·삭제하는 것, 실험 실행.
- `~/.claude/**`, 하네스 배포 경로.

## 5. 검증 방법 (필수)

저장소마다:
- `git ls-remote --heads --tags`를 개인 원격과 조직 원격에 각각 실행해 `ref SHA` 목록 diff 0 (6번은 로컬 ref와 비교).
- `gh repo view agent-discipline/<이름> --json visibility,description,defaultBranchRef` → PUBLIC · 설명 일치 · 기본 브랜치 일치.
- 로컬 `git remote -v` → origin이 조직 주소, `git status -sb` → 현재 브랜치가 `origin/<브랜치>`를 추적하고 ahead/behind 0.
- 개인 계정 쪽 `gh repo view` → 여전히 존재하고 PUBLIC.

## 6. stakes (필수)

- 판정: 낮음 — 근거: 내용 변경 없음, 기존 공개 저장소의 사본 생성이라 복구는 조직 저장소 삭제로 끝난다. 예외는 6번(첫 공개)으로, 공개는 되돌리기 어려우므로 안전 점검과 개별 확인을 선행 조건으로 둔다. 저장소 생성·push는 실행 직전 사용자 확인.

## 8. load-bearing 가정 (1~2개)

- 현재 gh 인증으로 조직에 저장소를 만들고 push할 수 있다(조직 role=admin 확인됨) → 가장 작은 claude-rules를 먼저 올려 실증한다.
- 로컬 clone이 개인 원격의 모든 브랜치 커밋을 갖고 있다(fetch 완료) → push 전 `refs/remotes/origin/*` 개수와 원격 브랜치 수 대조.
